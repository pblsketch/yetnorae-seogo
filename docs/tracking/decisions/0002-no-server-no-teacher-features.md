# 0002. 서버·계정·교사 기능 없음

## 배경
교실에서 쓰는 게임이라 교사용 편의 기능(진도 건너뛰기, 정답 보기, 특정 관이나 장면 바로 열기, 학생 진행 모아 보기)이 있으면 수업 시연과 점검에 편하다. 시리즈의 다른 작품(구운몽)에는 교사용 주소와 진행을 바꾸는 주소 인자(`?fixture=`)가 있었다. 한편 학생 기록을 서버로 모으면 개인정보 처리 책임과 운영 비용이 생긴다.

## 결정
서버, 계정, 네트워크 전송, 분석 도구를 두지 않는다. 교사 기능을 하나도 두지 않는다: 정답 보기, 장면 건너뛰기, 주소로 관·장면 열기, 숨은 미리보기 주소, 진행을 바꾸는 주소 인자. 사용자가 "제작자가 정해 놓은 대로 게임을 한다"고 분명히 정했고, 숨은 미리보기 주소도 거절했다. 점검에 필요한 상태는 점검 도구가 페이지를 열기 전에 로컬 저장소에 기록을 넣는 방식으로만 만든다.

## 다른 선택지
- **교사용 숨은 주소만 두기**: 학생이 주소를 알게 되면 순서를 건너뛸 수 있고, 형식 판단을 되풀이하게 하는 학습 설계가 무너진다. 사용자가 명시적으로 거절했다.
- **점검용 입구를 제품에 두고 배포 때 끄기**: 빌드 단계가 없는 정적 사이트라 '배포 때 끄기'를 보장할 장치가 없다.
- **학생 기록을 서버로 모아 교사가 보기**: 서버 운영, 개인정보 동의, 학교 망 차단 문제가 생긴다. 교사는 학생이 내려받은 결과 카드 PNG로 진행을 본다.

## 결과
- 제품 코드는 주소(`location`)를 읽지 않는다. 엔진·한 판·보스·이야기 점검이 소스를 훑어 주소 인자 읽기, 점검용 전역, 흉내 함수를 찾으면 실패한다.
- 교사가 수업 전에 특정 관을 보여 주려면 실제로 그 관까지 진행한 기록을 써야 한다.
- 점검은 상태를 넣은 장면 점검과, 상태를 넣지 않고 처음부터 끝까지 가는 완주 점검을 함께 둔다. 완주는 실제 시간이 걸린다(박자 방식 약 42분).
- 다시 넣지 않는다. 교사 기능이 '도움이 될 것 같아서' 다시 들어오면 이 결정과 충돌한다.
