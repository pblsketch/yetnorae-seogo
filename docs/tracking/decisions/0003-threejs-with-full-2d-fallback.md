# 0003. Three.js 3D 디오라마와 게임 전체 2D 그림 판

## 배경
게임의 핵심 장치는 '갈래의 형식을 닮은 건축'이다: 4·8·10구 층이 쌓이는 향가 탑, 3장 6구의 시조 정자와 종장 첫 계단 세 칸, 기둥이 넷씩 되풀이되는 가사 회랑, 가운데 층만 늘어난 사설시조 정자. 이것을 공간으로 보여 주려면 3D가 맞다. 그러나 학교 크롬북과 오래된 태블릿에는 WebGL2가 없거나 느린 기기가 있고, 시리즈는 빌드 없는 정적 페이지 방식이다.

## 결정
3D는 `vendor/three/`의 Three.js 0.186.1을 import map으로 불러 저폴리 디오라마로 조립하고, 인물은 2D 종이 인형 스프라이트로 둔다. 관마다 한 화면짜리 디오라마로 만들고 회랑으로 잇는다(자유 탐험 없음). 성능 상한은 관 하나의 그리기 호출 60회, 픽셀 비율 1.5, 실시간 그림자와 후처리 없음이다. WebGL2가 없거나 3D 그림판을 만들지 못하면 그 창은 **게임 전체**를 2D 그림 판으로 같은 규칙대로 진행한다. 관 모형과 작품 방, 보스는 3D와 2D 두 구현을 같은 약속으로 가진다.

## 다른 선택지
- **2D만**: 건축이 형식을 보여 주는 장치가 평면 그림으로 줄어든다. 시리즈의 첫 3D 작품이라는 목표에도 맞지 않는다.
- **3D만(안 되는 기기는 안내만)**: 학교 기기 일부에서 수업 자체를 할 수 없다.
- **일부 장면만 2D 대체**: 3D에 기대는 장면(초가 장면, 「상춘곡」 걷기, 좀 대왕, 가객 행렬)에서 막히면 끝까지 갈 수 없다.
- **게임 엔진·번들러 사용**: 빌드 단계가 생기고 시리즈 방식과 어긋난다.
- **넓은 자유 탐험 공간**: 저사양 기기 성능과 길 잃음 문제가 커지고, 건축과 형식의 대응이 한눈에 보이지 않는다.

## 결과
- 모든 관 모형·방·보스 장면을 두 벌 만들고, 점검도 3D(SwiftShader)와 3D를 끈 브라우저(2D) 두 번 한다. 완주 점검의 태블릿 크기는 강제 2D다.
- 제품에는 2D를 강제하는 스위치가 없다(주소 인자 금지와 같은 까닭). 2D를 보려면 WebGL을 끈 브라우저로 연다.
- Three.js 0.186은 WebGL2만 쓰므로 WebGL1만 있는 기기도 2D가 된다.
- 관 모형 손잡이 모양을 `normalizeWing`으로 하나로 맞추고, 2D 누를 자리는 세계 바탕이 만든다. 새 관 장치는 두 구현과 두 점검이 함께 필요하다.
